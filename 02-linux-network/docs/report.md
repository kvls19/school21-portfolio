## Part 4. Сетевой экран

- **4.1. Утилита iptables.** На ws1 в `/etc/firewall.sh` добавлены разрешения входящих TCP-пакетов на порты 22 и 80. Для исходящих ICMP echo-reply правило DROP расположено перед ACCEPT.

  ws1: содержимое `/etc/firewall.sh`, запуск и ping к ws2 — 4 ответа из 4.

  ![ws1 — правила фаервола, запуск и ping до ws2 без потерь](img/part4-ws1-firewall.png)

- На ws2 для исходящих ICMP echo-reply правило ACCEPT расположено перед DROP. Разрешены входящие TCP-пакеты на порты 22 и 80.

  ws2: содержимое `/etc/firewall.sh`, запуск и ping к ws1 — 0 ответов из 4.

  ![ws2 — правила фаервола, запуск и ping до ws1 со 100% потерь](img/part4-ws2-firewall.png)

- Правила проверяются по порядку: на ws1 исходящий echo-reply отбрасывается первым правилом DROP, поэтому разрешающее правило ACCEPT недостижимо и ws1 не отвечает на ping. На ws2 echo-reply разрешается первым правилом ACCEPT, поэтому запрещающее правило DROP недостижимо и ws2 отвечает на ping. Исходящие echo-request этими правилами не блокируются.

- **4.2. Утилита nmap.** При проверке ws1 с ws2 команда `ping -c 4 192.168.100.10` не получила ответов (100% потерь), а `sudo nmap -sn 192.168.100.10` показала `Host is up`. Блокировка ICMP echo-reply не означает, что машина выключена.

  ws2: проверка доступности ws1 с помощью ping и Nmap.

  ![Ping без ответов и Host is up в Nmap](img/part4-nmap.png)

В `FORWARD` разрешены исходящий трафик из локальной сети, пакеты установленных и связанных соединений и перенаправленные TCP-пакеты к Apache на ws22.
